# dsh-autohandoff · 新项目自动铺双机交接

**解决的问题**：以前每个新项目都要手动跑一次 `python 公共层\bin\装交接.py <目录> --append-agents`，
忘了就出现"这个项目没有 `bin\打包进度.py`、没法打包交接、AGENTS.md 里也没有交接规矩"。

**现在的行为**：只要一个目录成为"项目"——即在它里面第一次开会话（包括子代理）——插件就会检查并补铺：

```
<项目>\
├── bin\打包进度.py        ← 标准脚本（取自 公共层\bin\模板\）
├── bin\接手进度.py
├── 收件箱\README.md
├── 发件箱\README.md
└── AGENTS.md              ← 补「## 交接（本项目自带）」+「## 共用工具」两节；没有就新建骨架
```

## 触发与排除

| 项 | 规则 |
|---|---|
| 触发 | `agent/created`：任何会话/子代理创建时，取它的工作目录 |
| 只认 | **桌面的一级子目录**（`桌面\<项目>`，与 `公共层\` 同级）。项目内部的子目录不触发 |
| 跳过 | 已有 `bin\打包进度.py` 的目录（幂等）；`公共层`；`config.exclude` 里的名字；**含 `.no-handoff` 文件的目录** |
| 退出 | 不想被铺的目录里放一个空的 `.no-handoff` 文件即可（临时草稿、素材中转站之类）；删掉它就恢复自动铺 |
| 失败 | 不打断会话，只写日志 |

## 配置（`cordis.patch.yml` 的 `config`）

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉就完全不动 |
| `python` | `python` | 调 `装交接.py` 用的解释器（脚本只用标准库） |
| `exclude` | 空数组 | 要跳过的目录名（每台机器不同，按需追加） |

## 日志与手动兜底

- 每次动作（OK / FAIL）追加到 `公共层\_日志\自动交接.log`，含被铺目录与脚本输出。
- 插件没跑（例如新机器还没装）时手动等价操作：

```cmd
cd 桌面\公共层
python bin\装交接.py ..\新项目 --append-agents --init-agents   :: 铺一个
python bin\装交接.py --scan                                    :: 看桌面上谁还缺
python bin\装交接.py --scan --apply                            :: 一次补齐
```

## 边界

- 只铺**交接脚手架**，不写项目内容；新项目的 `AGENTS.md` 正文（这是什么、先读什么、已知坑）仍需项目自己补。
- 不打包、不接手；打包/接手仍是各项目 `bin\` 里那两个脚本的事。
- 插件装在本机 profile 里，`公共层\plugins\` 下这份是可移植源（换机时随插件一起带走）。
