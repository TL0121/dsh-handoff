# 坑与教训（按症状组织）

> 下列都是真踩过的坑，每条写清**症状 → 原因 → 修法**。
> 修法已经写进脚本与插件，别"顺手改回去"。

## 1. 脚本一跑就在控制台炸 / 输出是方块

- **症状 A**：`python bin\接手进度.py` 校验通过后直接抛 `UnicodeEncodeError`，文件一个没写。
- **症状 B**：在 agent / pwsh 里读 `python bin\打包进度.py --list`，中文全是方块（退出码还是 0）。
- **原因**：Windows 控制台是 cp936。GBK 里没有的符号会**抛异常**（A）；被管道/重定向捕获时仍写 cp936 字节，
  读取端按 UTF-8 解就是乱码（B）。
- **修法**：脚本开头按**是否终端**分流——

  ```python
  for _s in (sys.stdout, sys.stderr):
      if _s.isatty():
          _s.reconfigure(errors="replace")                    # 人看：控制台编码
      else:
          _s.reconfigure(encoding="utf-8", errors="replace")  # 管道/agent：UTF-8
  ```

## 2. 临时目录跑到工作区外，被沙箱拒绝

- **症状**：`PermissionError`、或 `tempfile.gettempdir()` 悄悄回落到 cwd。
- **原因**：DSH 沙箱只放行**会话工作区**内的写入；系统 Temp 在区外。
- **修法**：环境包装器把 `TMP/TEMP` 指到 `<工作区>\.dsh\tmp`；判定"当前属于哪个项目"时
  **只认桌面的直接子目录**，不要按 `.dsh` 向上猜（用户主目录也有 `.dsh`，会猜错到工作区外）。

## 3. 自检脚本在会话里"挂死"，单核 100%，一行输出都没有

- **原因**：脚本把临时目录写死成 `tools\tmp`（工作区外）→ `PermissionError`；
  CPython 的 `mkdtemp` 在 Windows 上把 `PermissionError` 当"重名"无上限重试（`TMP_MAX` ≈ 21 亿次）。
- **修法**：临时目录跟随 `TMP`（`tempfile.mkdtemp()`），不要写死路径；诊断脚本改成逐行 `flush` 打印。

## 4. 插件里 `spawn` 子进程报 `EPERM`

- **原因**：沙箱内带管道 stdio 的 `spawn` 会同步抛 `EPERM`（命名管道不可用）。
- **修法**：先试 `['ignore','pipe','pipe']`，捕获 `EPERM` 后退化成 `['ignore','ignore','ignore']`，
  并以"目标文件是否落地"判成功，而不是只看退出码。

## 5. Windows 上建符号链接要管理员

- **症状**：`New-Item -ItemType SymbolicLink` → "此操作需要管理员权限"。
- **修法**：目录用 **junction**（`New-Item -ItemType Junction`），免提权；包管理器之后重装会自己收敛。

## 6. 中文文件名在对方机器上变乱码

- **原因**：macOS 自带 `zip` 不带 UTF-8 名称标记（EFS），Windows 解压按本地代码页。
- **修法**：统一用 Python `zipfile` 打包（自动写 UTF-8 标记）。

## 7. 把 A 项目的包合进了 B 项目

- **原因**：旧脚本不校验来源，解压时在 B 里凭空造出 `A/` 子树。
- **修法**：包内 `MANIFEST.scope` = 项目目录名；接手前先比对，不符直接拒（`--force` 才强解）。

## 8. 同一个包接了两遍，文件被覆盖回旧版

- **原因**：没有签名记录，而 `收件箱/README.md` 却写着"有防重复"——文档与代码不一致本身就是诱因。
- **修法**：`收件箱/.已接手.json` 记录每个包的哈希；同字节包再合直接拒。**这个文件不要删**。

## 9. 接手完脚本/规则变旧，下一轮又出问题

- **原因**：进度包会携带 `bin/`、`AGENTS.md`、规则文件（忽略清单只剔 `收件箱/`、`发件箱/`、`.dsh/` 与缓存）；
  对方用旧脚本打的包，会把本机刚升级的脚本冲回去。
- **修法**：接手后做**归一化** —— `装交接.py <项目>` 刷 `bin/`，再把母版规则拷进项目根。
  注意 `--scan --apply` 的判据是"没有 `bin/打包进度.py` 才算缺"，对已有脚本的项目**无效**，必须显式传项目名。

## 10. 规则文件"唯一副本"与"每项目一份"打架

- **症状**：§1.2 说别复制，§4.0 又说要拷进每个项目。
- **修法（v3.2 起）**：**母版**在公共层；各项目根放同内容副本随包传输；规则首行写版本号
  `改版 vX.Y`，接手脚本按版本号决定是否用母版覆盖（母版新→归一化；包内新→只告警不降级；`--no-sync-rules` 关）。

## 11. 项目自己的 `tools/` 被当成平台件漏掉

- **原因**：忽略清单里写着 `tools/`（历史遗留：当时平台件放在 `<工作区>\tools`）。
- **修法**：从忽略清单移除 `tools`；平台件只留在公共层（不在任何项目里，本来就不会进包）。
  项目自己的 `tools/`（构建脚本之类）必须跟着包走。

## 12. "包打成功"不等于"文件都进去了"

- **原因**：`os.walk` 遇到权限拒绝的目录**静默跳过**，不报错。
- **修法**：打包前 `--list` 记文件数，打包后核对包内条目数（= 文件数 + 2 个元数据）；
  目录里有锁死的东西时先处理权限。

## 13. 收件箱里一堆包，认不出哪个是哪个项目的

- **修法（v3.3 起）**：包名以项目名打头 `<项目名>-进度-YYYYMMDD-HHMM-<机器>.zip`；
  旧名字的包照样能接（只认 `MANIFEST.scope`），新旧混放不冲突。

## 14. 自动铺交接把 AGENTS.md 追加了两遍

- **原因**："是否已铺"只认固定标题；项目用了别的措辞（如把交接写在「## 范围」里）就被判成"没铺"。
- **修法**：检测键放宽到内容特征（`bin\打包进度.py`、`本项目自带一套交接`、`共用工具`、
  正斜杠路径等）；同时给 `AGENTS.md` 的追加做幂等测试。

## 15. 新项目忘了铺交接，等到要交接才发现

- **修法**：插件 `dsh-autohandoff` 监听 `agent/created`，桌面一级目录第一次开会话时自动铺；
  不想被铺的目录放一个空 `.no-handoff`。插件失败只写日志，不打断会话。

## 16. 两机的解释器名不同（`python` vs `python3`）

- **修法**：脚本只用标准库，不写死解释器；插件的解释器按平台选首选（mac `python3`、win `python`），
  找不到再试另一个（`ENOENT` 才换，`EPERM` 是沙箱问题另说）。

## 17. 规则/脚本版本悄悄分叉

- **修法**：规则首行是唯一版本源（`改版 vX.Y`）；脚本指纹（sha256）留底；
  每次改动走"改源 → 自测 → 同步部署 → 归一化项目 → 重打引导包"。

## 18. 别把备份当同步

- 把整个目录 `cp -R` 一份当"备份"，会双份占空间，还容易和同步盘/网盘打架；
  要留档就打成交接包（可校验、可还原）。

## 19. 只用 `posixpath` 校验包内路径，在 Windows 上会被反斜杠绕过

- **症状**：`safe_rel("..\\..\\evil.txt")` 原样放行，`os.path.join(ROOT, ...)` 之后实际写到项目根之外。
- **原因**：zip 条目名按 POSIX 规则处理，但 Windows 上 `\` 也是分隔符；而且包内的
  `MANIFEST.json` 与 sha256 都是**打包方自己写的**——四道关（scope / 签名 / 逐文件哈希 / 解压）
  挡不住"自己声明自己校验"的包。路径安全只能靠解包这一侧。
- **修法**（已写进 `接手进度.py`）：
  1. `safe_rel()` 遇到 `\` 一律拒绝（打包端本来就做 `rel.replace(os.sep, "/")`，合法包不可能有反斜杠，零误伤）；
     同一条规则顺带挡住 UNC（`\\srv\share`）与盘符；
  2. 写入前再校验一次 `within_root()`：`os.path.realpath(目标)` 必须仍落在项目根内 —— 顺带挡住
     "父目录是指向根外的符号链接 / 目录联接"这种走法；
  3. 越界条目在 v3.5 起**不再"跳过继续"**，而是整包拒收（见下一条）。

## 20. 接手成功 ≠ 发件箱里的包已经送出去了

- **症状**：在项目里接手一个包，`发件箱/` 里"打好但还没拷给对端"的包一起消失了。
- **原因**：v3.1~v3.4 把"清发件箱"当成接手后的自动收尾，隐含假设"发件箱里的包都已送达"。
  这个假设在"先打包、过一会儿再传"的流程里不成立。
- **修法（v3.5）**：默认**保留**发件箱，只有显式 `--clean-outbox` 才清第一层 zip；
  清掉了谁写进接手记录的「收尾」小节。

## 21. 越界条目只跳过、却照样记签名

- **症状**：包里有非法路径 → 那一条被跳过，其它文件照写，签名照样记；重试被"这个包已经接过"挡住，
  项目停在"更新了一半"的状态上。
- **原因**：写入与"记签名/清发件箱"是两段逻辑，拒收只影响前者。
- **修法（v3.5）**：写盘之前**全量预检**，任何一条越界/非法就整包拒收 —— 不写文件、不记签名、不清发件箱；
  `--force` 也不豁免路径校验（它只放宽 scope 与签名）。
